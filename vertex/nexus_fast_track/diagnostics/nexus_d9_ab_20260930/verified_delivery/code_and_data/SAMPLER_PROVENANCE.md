# D9 sampler comparison provenance

The frozen project flow is `x(t)=(1-t)noise+t*data`, with model velocity `v=data-noise`; its Euler sampler evaluates `t=i/20` for `i=0,...,19`. The independent DPM adapter uses `sigma=1-t`, passes `-v` as Diffusers `flow_prediction`, and preserves the exact supplied FP32 noise. It does not modify model weights, conditions, parents, thresholds, or GT.

Implementation: [Diffusers `DPMSolverMultistepScheduler` v0.40.0](https://github.com/huggingface/diffusers/blob/v0.40.0/src/diffusers/schedulers/scheduling_dpmsolver_multistep.py), installed scheduler source SHA-256 `0dd5333bd7b900b117d34f151adfc4b181dbb2062ca860105658037a0fe5dc06`. [Official scheduler documentation](https://huggingface.co/docs/diffusers/main/api/schedulers/multistep_dpm_solver) documents `use_flow_sigmas`, `flow_prediction`, `dpmsolver++`, order 2 and `final_sigmas_type="zero"`. The tested dependency is `diffusers==0.40.0`; local CPU tests used `torch==2.8.0`. Remote deployment must isolate Diffusers dependencies and keep the existing server Torch installation unchanged.

Diffusers 0.40.0 normally begins a 20-step flow schedule at `sigma=0.999`. `samplers.py` replaces only that scheduler's inference grid with `sigma=1,0.95,...,0.05,0` and corresponding 1000,...,50 scheduler timesteps. The first step is the official first-order update from pure noise. Because `lambda(sigma=1)=-inf`, the second step also uses the official first-order branch; steps 3–19 use its second-order midpoint branch, and the final `sigma=0` step uses its built-in first-order final branch. This preserves 20 model evaluations. Network output may be BF16; ODE state and updates are FP32. `schedule_metadata()` records the exact grid and policy for each generated tree.

`test_samplers.py` covers exact endpoints and time grid, constant velocity, a wrong-sign negative control, a nonconstant affine field against 20,000-step FP64 RK4, BF16 output and padding mask, and GT-oracle octree recovery. `test_evaluate_ab.py` exercises the original native exporter with Euler and DPM on a CPU oracle, and checks capacity abort remains in the 100-tree denominator. Results are in `sampler_test_results.json` and `evaluate_test_results.json`. These are analytic/CPU checks, not a trained-model or GPU evaluation.
