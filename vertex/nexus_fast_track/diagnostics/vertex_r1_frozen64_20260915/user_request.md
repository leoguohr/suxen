**这次有实质性进展：R1 已经在这组验证噪声上学会了有效去噪，不应再把它和 R0 一起归为“噪声分支没有学会”。**

**下一步建议：保留 R1 第 1000 步的权重，不重新训练，先补做 64 份独立噪声评估；几何恢复验证通过后，再进入随机时间的 B2。现在仍然不需要增加 mesh 数量。**

我复算了 **512 份验证预测、30 份训练缓存预测**，核对了训练噪声序列，并在本地运行了 **34 项测试，全部通过**。包内没有完整模型权重，所以没有重跑你服务器上的大模型；下面会区分保存数组的复算结果与报告中的前向诊断。[复核结果](sandbox:/mnt/data/vertex_b1_recomputed_audit.json) · [本地测试记录](sandbox:/mnt/data/vertex_b1_local_tests.txt)

## 1. 这次确实跑对了实验，而且初始化修改有效

本轮两组都只训练了 **`nexus_2k_000105` 这一个 8 顶点物体**，固定 depth 9、GT parents、点云与法向、`t=0.5`；每次更新使用 8 份新噪声。两组均从头初始化，没有加载旧 A 权重，前 500 步实际使用的训练噪声哈希逐项一致。[实验协议](sandbox:/mnt/data/vertex_b1_review/Vertex_B1_R0_R1_results/PROTOCOL.md)

最有意义的是先比较**相同训练步数**：

| 指标                | R0：500 步 |     R1：500 步 |    R1：1000 步 |
| ----------------- | -------: | -----------: | -----------: |
| 验证平均 velocity MSE | 1.124753 | **0.009401** | **0.001903** |
| 验证最差 velocity MSE | 1.421158 |     0.025985 | **0.006795** |
| 精确恢复整数坐标集合        |     0/16 |    **16/16** |    **16/16** |
| 训练缓存输入 MSE        | 0.993902 |     0.005315 | **0.001224** |

**同为 500 步，R1 的平均 MSE 已经约为 R0 的 `1/120`。因此，改善并不只是因为 R1 多训练了 500 步。** R1 从第 400 步开始，这 16 例坐标集合就全部正确；第 850 步开始，所有验证例的 MSE 都低于 `0.01`。[逐步复算记录](sandbox:/mnt/data/vertex_b1_recomputed_audit.json)

这里有一个小但重要的解释：`training_cache` 是第一步真正训练过的一份输入，**只参与过一次训练**。它不是反复训练的固定回归问题，不能单凭它的结果判断“A 式固定输入 overfit”是否成功。

## 2. 问题现在定位到什么程度？

### R0 确实接近“输出常数”，R1 则恢复了噪声响应

我用保存的 16 份预测数组，额外计算了不同噪声之间的输出变化。对于当前固定目标、`t=0.5` 的问题，正确关系是：

$$
\Delta v=-2\Delta x
$$

复算得到：

| 跨噪声响应指标     |      R0：500 步 |     R1：1000 步 | 理想值 |
| ----------- | ------------: | ------------: | --: |
| signed gain | **−0.000167** | **−1.972758** |  −2 |
| 相对响应误差      |  **0.999916** |  **0.037618** |   0 |

**R0 的预测速度平均值约为 `0.124`，而目标占据比例为 `0.125`；换噪声后，输出变化非常小。** 这与“主要输出接近占据均值的常数，没有有效利用噪声输入”的解释一致。

R1 已经明显不同：它会随输入噪声作出接近正确方向和幅度的变化。这是支持“它开始学会去噪规律，而不只是记住某份固定噪声答案”的直接证据。[复算指标与方法](sandbox:/mnt/data/vertex_b1_recomputed_audit.json)

注意，上表是**从保存的 autocast 预测计算出的跨噪声统计**，不是报告中那四个 FP32 局部扰动测试，不能拿它替代原来的判定。

### 初始化组合是有效修正，但还不能拆分出唯一根因

本轮 FP32 探针还显示，在相同的第 500 步：

| 特征 RMS        |     R0 |    R1 |
| ------------- | -----: | ----: |
| 第一个 block 输出  |  1.478 | 0.185 |
| 最后一个 block 输出 | 17.400 | 0.225 |

这与 R1 更好地保持和利用噪声输入的解释相符，但**不能仅凭相关变化证明某一项初始化是唯一根因**。目前能支持的是：

> **depth embedding 缩小初始化、time MLP 小尺度初始化、cross-attention 输出零初始化，这个组合在当前任务和训练种子下显著改善了学习。**

暂时保留整个 R1 组合即可。**现在没有必要立即拆成多组消融，也不应优先改 flow 符号、占据阈值或删除网络模块。** 先确认这条有效路径能继续完成后面的任务。[R1 初始化与训练入口](sandbox:/mnt/data/vertex_b1_review/Vertex_B1_R0_R1_results/code/scripts/train_vertex_a100_b1.py)

## 3. 为什么还是 `passed=false`？

**因为最后一个未满足的条件是局部响应误差，不是顶点坐标，也不是 velocity MSE。**

R1 第 1000 步的四个 FP32 局部扰动探针是：

| 噪声 seed     | signed gain |     相对响应误差 | 原门槛        |
| ----------- | ----------: | ---------: | ---------- |
| 8000000     |     −1.9808 |     0.0362 | 通过         |
| 8000001     |     −1.9993 |     0.0419 | 通过         |
| **8000002** | **−1.9262** | **0.1214** | **超过 0.1** |
| 8000003     |     −1.9957 |     0.0380 | 通过         |

因此，原程序的 `passed=false` **判定没有算错**；它也因此没有自动触发 64 份独立噪声测试。[R1 最终原始评估](sandbox:/mnt/data/vertex_b1_review/Vertex_B1_R0_R1_results/run/B1_R1/evaluation-001000.json)

但这与前几轮失败的严重程度不同。我额外检查了 R1 的全部验证占据估计：它们与真实 `0/1` 标签的**最大绝对误差约为 `0.179`**，到分类阈值 `0.5` 的**最小正确侧余量约为 `0.321`**。所以，16/16 并不是大量数值刚好卡在阈值边缘而侥幸判对。[复算结果](sandbox:/mnt/data/vertex_b1_recomputed_audit.json)

**这里我调整上一轮的建议：将 `relative_response_error ≤ 0.1` 设为阻止一切后续验证的硬门槛，过于保守。** 它是一个工程诊断阈值，不是正确恢复整数坐标集合的数学必要条件。

不过，也不能看到 `0.1214` 就事后把阈值改成 `0.15`，然后宣布旧实验通过。正确处理是：

**保留“原严格协议未通过”的记录，新增一次冻结模型的独立评估，把几何恢复与局部响应诊断分开报告。** 局部响应偏差仍然值得跟踪，尤其后面要检验完整采样时，不能直接忽略。

## 4. 下一步先做什么：冻结 R1，补独立验证


这次重点分别报告：

其中，几何/回归检查仍要求 **64 例全部整数坐标正确，并且每例 MSE ≤ 0.01**；原来的响应阈值也不修改。

### 我已经整理了一个只评估、不训练的入口

[下载冻结模型评估脚本](sandbox:/mnt/data/evaluate_vertex_b1_frozen.py)

## 5. 接下来才是 B2：从固定时间扩展到随机时间

**B2 应从当前有效的 R1 权重继续，不需要再从头做 A。**

保持同一个 mesh、depth 9、GT parents、固定点云与法向、原速度目标和阈值；保留优化器状态及当前 `lr=1e-5`、8 份噪声累积等设置。主要变化只有：

$$
t=0.5
\quad\longrightarrow\quad
t\sim U[0,1)
$$

每个 microbatch 独立采样时间和噪声。首轮可以预先设定 **1000 次更新、每 100 次开发验证**，这是下一轮的排错预算建议，不是已验证的最优训练量。

这里有两个具体实现点：

**第一，现有 B1 代码把训练时间和响应诊断写死在 `0.5`。** 需要明确增加 B2 模式，不能只把报告中的 `phase` 改成 B2。开发验证按 `t=0、0.1、0.3、0.5、0.7、0.9、0.95` 分别报告，避免高时间步的好结果掩盖低时间步问题。

**第二，B2 必须加入“从纯噪声开始”的单层采样。** 仍然给 GT parents，用 20 步 Euler 生成 depth 9，检查多个新种子是否恢复那 8 个正确整数坐标。40 步可以作为积分敏感性对照，但不能代替正确性检查。

另外，固定目标下其他时间步的理想响应是：

$$
\Delta v=-\frac{1}{1-t}\Delta x,\qquad t<1
$$

**不能对随机时间的所有探针继续要求 signed gain 等于 −2。**

B2 通过后，再做 **C：单 mesh 全树生成 → D：2–4 个形状的条件切换 → 10/20 个 mesh**。当前结果还没有验证纯噪声 ODE 生成、完整八叉树生成或多物体 VecSet 条件利用，不能跳过这些阶段。
