# 失败诊断：这套训练方法为什么没修好

> **结论先行**：500 步预算耗尽，**最佳 face F1 = 0.995265 @ new_updates=0** ——
> 就是父模型本身，**训练一步都没能超越它**。目标 0.997 差 0.0017，`stop_reason = "budget_exhausted"`。
>
> 根因可量化：Hard4 的等权分组使**单个 FP 的权重是单个 TN 的 178.7 倍**，
> 叠加分类器**缺少独立阈值项**，导致决策边界单侧漂移。

### 1.2 病征：边界单侧漂移


FP 在降，FN 在涨。两者之和（= 总错误数）：`53 → 58`，**在变差**。

micro-F1 = `2·TP / (2·TP + FP + FN)`，分母的 FP+FN 增大而 TP 不变 → F1 下降。

**这是"模型学会更保守地判正"的教科书信号**：把 FP 换成 FN 的减少。

## 2. 根因一：Hard4 的等权分组（可量化）

```python
loss = (numerator / counts.clamp_min(1)).sum() / 4
```

4 个组**各占 1/4 权重，与组大小无关**。所以单样本权重 = `(1/4) / |group|`。

以 face 分支为例（全体 50 网格）：

| 组 | 样本量 | 每组权重 | **单样本权重** |
|---|---|---|---|
| TN | ~8,400 | 1/4 | 2.98e-5 |
| TP | ~5,576 | 1/4 | 4.48e-5 |
| **FP** | **47** | 1/4 | **5.32e-3** |
| FN | 6 → 17 | 1/4 | ~0.15 ~ 0.014 |

$$ \frac{w_{FP}}{w_{TN}} = \frac{(1/4)/47}{(1/4)/8400} = \frac{8400}{47} = 178.7 $$

**每个 FP 的梯度贡献是每个 TN 的约 179 倍。**

（此数值由 `code/verify_math.py` 第 5 节自动计算输出。）

### 2.1 后果

梯度被极少数稀有样本主导。模型的"最优解"变成**让那 47 个 FP 消失**。

而由于分类器的结构限制（见 §3），它做到这一点的**唯一途径是整体压低判正倾向** ——
代价就是 FN 暴涨。

**这解释了为什么 500 步里没有任何一次能超过父模型。** 不是训练不收敛，是收敛到了更差的点。

### 2.2 为什么这个设计看起来合理但实际有害

设计者的意图显然是"类别不均衡 → 让每个类别等权"。这在**组大小可比**时是对的。

但 face 分支的实际分布是 **5576 : 8400 : 47 : 6** —— 最大组与最小组差 **1400 倍**。
等权分组把这种极端不均衡**放大**成了一组权重 179× 的主导项，而不是修正它。

## 3. 根因二：分类器没有独立阈值项 ★

看 face 分类器：

$$\text{logit}_{\text{face}}(i,j,k) = \text{FACE\_SCALE} \cdot \left(\text{Area}^2_{\text{space}} - \text{Area}^2_{\text{time}}\right)$$

**没有 bias。阈值被硬钉在 0**（即 `Area_space == Area_time` 处）。

而训练只能改 `face_embedding`（1024→32 的线性投影）。**无法独立调节这个阈值。**

### 3.1 为什么这是致命的

模型想"少判正"时，只有两条路：

1. **整体缩放嵌入空间** → 同时改变所有样本的 logit 尺度
2. **旋转嵌入空间** → 同时改变所有样本的相对位置

**两条路都是全局操作，无法"只移动边界不动判别力"。**

正常做法应该是 `logit = w·z + b`，其中 `b` 单独承担阈值调节。
这里 `b ≡ 0`，阈值与嵌入尺度**强耦合**。

### 3.2 与 §2 的耦合

Hard4 把巨大的梯度压向"消灭 47 个 FP" → 模型必须降低判正倾向 →
但它只能通过全局缩放/旋转实现 → **必然连累 FN**。

**两个缺陷叠加，形成了观察到的单侧漂移闭环。**

---

## 4. 次要因素

| # | 因素 | 影响 |
|---|---|---|
| 1 | **hard negative 全程不刷新**（`refresh=False`） | 47 个 FP 被钉死为固定靶。它们本身就是父模型在当前边界下的最难点 —— 钉死等于把边界往它们那侧拉 |
| 2 | **lr = 1e-4 偏大** | 继承了父训练后期的 lr，微调阶段偏大。配合 179× 加权梯度容易过冲（F1 在做 ±0.001 的震荡） |
| 3 | **batch 只有 5 个 mesh** | 随机负样本每 epoch 全部重抽，小批下方差高 |
| 4 | **随机负样本与评估候选集语义不一致** | 训练负样本 = 随机 + 47 固定；评估候选 = **预测边构成的团**。两者分布不同 |

---

## 5. 独立硬上限：strict 指标结构上封顶

协议写死：

```
frozen_edge_strict_ceiling = 40
```

因为 edge 分支冻结且有 **21 FP + 3 FN**，所以**最多只有 40 个 mesh 可能 joint-perfect**。

实测最佳 39 —— 只剩 1 个网格的空间。

> 如果目标本质是"整体完美"，那么**只解冻 face 分支在结构上就不够**。
> edge 的 24 个错误是死锁的，无论 face 训多久都无法消除。

## 6. 修改建议（按预期收益排序）

| # | 改动 | 理由 | 改动量 |
|---|---|---|---|
| **1** | **给 face logits 加可学习标量 bias** | 解耦阈值与嵌入尺度。单项收益最大 | 极小 |
| **2** | **Hard4 改为按组大小加权**（或改用 `pos_weight` / focal loss） | 直接消除 179× 放大 | 小 |
| **3** | **hard negative 周期性刷新** | 固定靶会把边界锁死在父模型的失败模式上 | 小 |
| **4** | **解冻 edge 分支**（或放宽 strict ceiling） | 不改则 joint-perfect 结构上封顶 | 大 |
| **5** | lr 降到 1e-5 量级 + warmup | 微调后期 1e-4 配合大权重梯度会过冲 | 极小 |
| **6** | 增大 batch（5 → 10~20 mesh） | 降低无状态负采样的方差 | 小 |

### 6.1 建议 1 的实现

```python
# 原实现
def face_logits(embedding, triples):
    ...
    return FACE_SCALE * (FACE_FACTOR * (areas[0] - areas[1]))

# 建议改为（新增一个标量参数）
class FaceClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.bias = nn.Parameter(torch.zeros(()))     # 可学习阈值

    def forward(self, embedding, triples):
        ...  # 同原逻辑得到 raw
        return FACE_SCALE * (FACE_FACTOR * raw) + self.bias
```

同时把 `bias` 加入 `FACE_NAMES`（可训练集合），并注意：

- 它**不在** `face_embedding` 模块里 → `assert_trainable_is_face_only` 需要放宽
- `frozen_hash` / `adam_frozen_hash` 的排除集需要同步更新
- 优化器仍需在此参数上有状态（父代没有它 → 新参数 Adam 状态从零开始，这是可接受的）

### 6.2 建议 2 的实现

```python
# 原：每组等权
loss = (numerator / counts.clamp_min(1)).sum() / 4

# 建议 A：按全局组大小加权（组均值 × 组占比）
weights = counts / counts.sum()                       # 组大小占比
loss = (weights * (numerator / counts.clamp_min(1))).sum()

# 建议 B：focal loss（降低已分类好的样本权重）
#   直接把 hard4_sums 里的 BCE 换成 focal BCE，分组保留
```

**建议 A 把单样本权重变得与组大小无关**，即 `w = 1/N_total`（常数）——
这就等价于普通的加权 BCE，消除了 179× 放大。

注意：建议 A/B **改变了损失语义**，会让结果与原配方不可比。若要"保持原配方同时修好"，
建议只做 1 + 3 + 5（不改损失形式）。

## 7. 复现时的检查清单

如果你要重新跑这套配方，在开训前确认：

- [ ] `face_logits` 是否有 bias？（原配方：无 → 预期会出现 FP↓/FN↑ 漂移）
- [ ] Hard4 是否等权分组？（原配方：是 → 预期 FP 主导）
- [ ] `fixed_hard_negatives` 是否 47 个且 `refresh=False`？
- [ ] `batch_for_update` 是否用**全局** update 序号算 epoch？（否则复现第一版的崩溃）
- [ ] 缓存审计是否在**最大网格**上做了 loss + 梯度位级比对？
- [ ] Adam step 计数器是否对齐到 `19356 + new`？
- [ ] 是否每 50 步校验 `frozen_hash` 与 `adam_frozen_hash`？
- [ ] 是否理解 strict 指标封顶在 40？

---

## 8. 一句话总结

> 这套方法的技术执行是**高质量**的（确定性、缓存审计、冻结校验、幂等续训都是教科书级），
> 但**目标函数的设计有两个结构性缺陷**：等权分组造成的 179× 权重放大，
> 以及分类器缺失独立阈值项。
>
> 两者叠加，使训练**必然**朝"少判正"的方向漂移 —— 500 步里没有任何一次能超过父模型。
>
> **修复成本极低（建议 1 + 2），但如果不改，复现只会得到同样的结果。**
